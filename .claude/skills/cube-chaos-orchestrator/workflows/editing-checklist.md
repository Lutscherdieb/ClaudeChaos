# Editing-only checklist

Rules that only apply when changing something that already exists, on top of whatever the matching content-type workflow (`content-cube.md`, `content-perk-family.md`, `content-class-species.md`) already covers for fresh creation. Read this *before* making the edit, not after — several of these are about not treating the edit as "just the DSL change."

- **An `Ability:`/`WorldAbility:`/`SpecialAction:` change updates its paired `Text:`/`Description:` in the same edit.** Not a follow-up, not optional, even for a one-word change (a direction changing from `North` to `East` means the word "above" in the prose has to become "to the east," not just the DSL token). This is `cube-chaos-scripting`'s Text:/Description: requirement plus `cube-chaos-rule-text`'s "rule text is never edited independently" principle, stated together because in practice they get missed together.
- **A changed positional/directional effect means checking the `Visual:` lines too**, not just the ability logic — a cube whose effect now reaches a different tile but still shows the old placement-preview marker is a real, easy-to-miss bug.
- **A perk-stacking behavior change means re-checking whether the "additional copies of this perk..." clarifying sentence is still warranted** — per `cube-chaos-rule-text`, that sentence belongs only when the re-trigger is a genuinely non-obvious/separate mechanism (like a repeated internal scan), not when stacking is just the natural consequence of a "first cube/target matching X" search. Don't add it reflexively just because a perk stacks; don't leave a stale one in either if a rewrite changed the mechanism.
- **A sprite edit stays scoped to exactly the one tile being changed** — its full bounding box, including that tile's own border pixels — never a wider redraw of a shared sheet, even to "fix" something that looks inconsistent elsewhere. If the border itself needs regenerating for that tile, use the from-scratch generators in `cube-chaos-sprite-art`'s border-pattern library (position-based), never color-matching against another tile's pixels — that's what caused the DJ-headphones-bleeding-into-other-icons incident this skill set exists partly to prevent.
- **A grid-resizing sprite change (adding enough new content to need a bigger grid) relocates existing tiles' exact pixels, never redraws them** — extract each tile's current pixel box, paste into its new grid position unchanged, then add the new tiles. **Recompute every affected perk's slot index by counting every `PERK:` block in file order, including `IsUpgradeFrom:` ones** — an upgrade perk's slot is conventionally left blank, but it still occupies a position in the sequence in a file that has a real sprite sheet; skipping it in the count shifts every later perk one slot off and produces a silent `WARNING: Perk <name> ... with empty Image` (checkerboard texture in-game) instead of a load error. This is the single easiest step to get wrong when adding a perk to a file that already mixes regular and upgrade perks — see `cube-chaos-sprite-art`'s border-pattern-library section for the full incident writeup.
- **Adding/removing a `Value:` line changes what economy the perk participates in, not just a cosmetic number** — check `cube-chaos-scripting`'s Perk economy section before touching one on an existing perk. A plain class/species reward perk must have none at all; every other category (Curse/Blight/Boon/Terrain/Consumable/Golden/Neutral/CubeUpgrade) is expected to have one. Don't add one "just in case" to a reward perk — it makes the perk sellable in shops via `Sell_One_Positive`'s `IsLarger ValueOfPerk Target 0` filter, a real behavior change, not a no-op.
- **Renaming a `PERK:` breaks any self-name check silently** (`AmountOfPerksInInventoryWhich IsSameString NameOfPerk Test StringConstant <OldName>` keeps reading zero forever, no error) — if the perk being edited does this kind of self-reference anywhere, update the literal string too.
- **Always finish with a fresh test-launch and `Log.txt` check**, even for an edit that "should be safe" — a change that only touches prose or only touches a sprite can still desync the parser or collide with a filename, and the previous launch's clean log doesn't cover new edits made since.
- **Then regenerate the mod's README preview cards** (`python3 .claude/skills/cube-chaos-sprite-art/scripts/render_preview_cards.py`) — an edited `Description:`/`Value:`/icon that isn't reflected in `GameData/<Mod>/Preview/` is stale documentation, and it's easy to forget once the DSL/log-check part of the edit is already "done."
